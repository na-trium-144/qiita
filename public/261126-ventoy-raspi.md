# 1本のUSBで Ventoy と Raspberry Pi 起動ディスクを両立する

OSのインストールメディア、Raspberry Piの環境、大容量のデータ持ち運び用SSD の3つの役割を1本のUSB接続SSDに同居させる方法をまとめました。

* PC起動時： Windows / Ubuntu などのマルチブートインストーラーとして機能する（Ventoy使用）
* Raspberry Pi 3接続時： そのままRaspberry Piの起動ディスクとしてブートできる
* Windows / Linux / Mac 接続時： 余った領域を普段使いのUSBストレージとして自由に読み書きできる

※1つのOSイメージをx86系PCとARM系のRaspberry Piの両方で起動するわけではなく（アーキテクチャが異なるため不可能です）、1つのドライブ内にそれぞれのブート環境とデータ領域を共存させる構成です。

## 要件の整理とパーティション設計

### Ventoy側の制約

* デフォルトでは第1パーティションがISO置き場（exFAT）として初期化されますが、FAT32やNTFSなどで再フォーマットしても動作します。
* 第2パーティションがEFIシステムパーティション（FAT）であることが必須です。後ろに空きスペースを作ることは可能ですが、第2パーティションの中身や位置は変更できません。
* 第3パーティション以降に保存したISOファイルも起動可能です。4GB以上のISOイメージ（Windowsなど）を扱うため、ISO置き場は **exFAT** である必要があります。

### Raspberry Pi 3側の制約

* パーティションテーブル： Raspberry Pi 3でUSBブートを行う場合、パーティションテーブルは **MBR** である必要があります。
  * Raspberry Pi 4以降であればGPTも選択可能らしい？
* 第1パーティションが **FAT32** であり、ここにブート用ファイルが配置されている必要があります。
* デフォルトでは第2パーティション（ext4）がルート（`/`）になりますが、第3パーティション以降に逃がすことが可能です。ただし、Linuxのルートとして機能させるため **ext4** などのLinux用ファイルシステムである必要があります
  * exFATの直接利用や、exFAT上のイメージファイルをループバックマウントしてルートにする構成は難しいのではと思います

### 最終的なパーティション構成

以上の要件から、以下の4パーティション構成（MBR）を採用しました。

| パーティション番号 | ファイルシステム | 用途 |
| --- | --- | --- |
| 1 | **FAT32** | Raspberry Pi ブート領域 |
| 2 | **FAT16** | Ventoy ブート領域（EFI） |
| 3 | **exFAT** | Ventoy用ISO置き場 ＆ フリースペース |
| 4 | **ext4** | Raspberry Pi ルート領域（`/`） |

第3・第4パーティションの順序は入れ替え可能です。

## セットアップ手順

### 1. Ventoyのインストール

通常通りUSB SSDにVentoyをインストールします。この際、デフォルトでは第1パーティションがディスク最大サイズで作成されますが、後ほどパーティション構成を作り直すため、第1パーティションのサイズを最小限に設定し、ディスク後方に空きスペースを確保しておきます。

### 2. パーティションの再構成

GPartedなどのパーティション編集ツールを使い、第2パーティション（Ventoy本体）には触れずに以下の作業を行います。

1. 第1パーティションを削除し、Raspberry Piのブート領域として **FAT32** パーティションを先頭に作成する。
2. 第2パーティションの後ろにある空き領域に、第3パーティション（**exFAT**）と第4パーティション（**ext4**）を作成する。

### 3. Raspberry Pi用OSのインストールと設定変更

第1パーティション（FAT32）と第4パーティション（ext4）にRaspberry Pi用のOSを展開します。

今回は **Arch Linux ARM64** をインストールしたため、公式手順の展開先を第2パーティションから第4パーティションに読み替えるだけでスムーズに導入できました。

ルートファイルシステムが第4パーティションであることを認識させるため、第1パーティション内の `cmdline.txt` と、第4パーティション内の `/etc/fstab` の記述を書き換える必要があります。

* **`cmdline.txt`（第1パーティション内）：** `root=PARTUUID=...` となっている箇所を第4パーティションに変更（`-02` → `-04`）
* **`/etc/fstab`（第4パーティション内）：** ルート（`/`）のマウント対象を第4パーティションに変更

※試していませんが、Raspberry Pi OSなど、標準インストーラーでインストール先のパーティション番号を柔軟に指定できない場合は、一度別のSDカードやUSBメモリに通常通りインストールしたあと、それぞれのパーティションの中身をコピーして上記設定ファイルを書き換える方法が確実かもしれません。

さらに、fstabを編集して第3パーティションが起動時に自動マウントされるようにし、Raspberry Pi 側からも共有ファイルにアクセスできるようにしました。

### 4. ISOイメージの配置

第3パーティション（exFAT）に、WindowsやUbuntuなどのISOイメージを配置します。余った領域には普段使いのドキュメントやデータファイルをそのまま保存できます。

## 運用上の補足・小技（Tips）

### VentoyでのISO選択とUI表示

Ventoyの起動画面はデフォルトで第1パーティション内のISOのみをスキャンします。

* 第3パーティションにあるISOを起動したい場合は、起動画面で `F2` キーを押すことでファイルブラウザが開き、別パーティションのISOを選択してブートできます。
* 毎回 `F2` を押すのが手間な場合は、Ventoyのvlnk機能を使い、第3パーティション内のISOへのリンクファイルを第1パーティションに作成しておくと、起動直後のメインUIに一覧表示させることができます。
* 第1パーティションをスキャンする仕様上、Raspberry Piの起動用イメージ（`kernel7.img` など）もVentoyのメニュー一覧に表示されてしまいますが、実害はありません。

### Windows接続時にシステムパーティションを隠す・自動再生を防ぐ

Windows PCにこのSSDを接続すると、パーティション1・2・3 の3つがドライブとしてマウントされます。

※本来WindowsはEFIパーティションを自動で隠すはずだと思うのですが、なぜかパーティション2も表示されました。

* 普段使いの自分のWindows PCであれば、「ディスクの管理」や `diskpart` からパーティション1と2のドライブレター（ドライブ文字）を削除しておけば、次回接続時からも表示されなくなります
  * この設定はPC側OSのレジストリに記憶されるため、別のWindows PCに挿したときは再度表示されます
* GPTディスクであれば `diskpart` で特定のパーティションだけに非表示属性を付与できますが、MBRディスクでは属性変更がディスク全体に適用されてしまい、データ用のパーティション3まで見えなくなるため使えません。
* 自動ポップアップの抑止： 接続のたびにパーティション1・2がエクスプローラーで自動で開かれるのを防ぐため、それぞれのルートに以下の内容で `autorun.inf` を配置しました（Windows 11でも有効です）。
  ```ini
  [autorun]
  UseAutoPlay=0
  ```
* ファイル一覧の整理： 誤操作防止のため、パーティション1と2の中にあるファイルはすべて「隠しファイル」属性を付与して見えなくしています。

### Linux接続時にRaspberry Piのrootパーティションを隠す

Linux PCに接続すると、パーティション1・3・4 がマウント対象として表示されます。

このうち第4パーティション（ext4）については、`fdisk` などのツールでパーティションIDを `83`（Linux）から `93`（Amoeba / 隠しLinux領域扱い）に変更することで、デスクトップ環境などで自動マウントされるのを防ぎ、隠しパーティションとして扱うことができます。

パーティションIDを `93` に変更した状態でも、Raspberry Pi 3本体からのブートや動作には一切支障ありません。
